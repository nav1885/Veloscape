Sherpaa — Quick-Start Modes · One-Tap PR / Training / Recovery

Visual mockup of the mode-first pivot: replace the high-friction "plan a ride" flow with a one-tap mode picker. Built from the color tokens in src/constants/colors.ts and the layout in docs/design/QuickStartModes_HomeFlow_REVIEW.md (implements docs/amendments/QuickStartModes_Amendment.md). Not a screenshot — a faithful static render of the intended design. All 10 of Stencil's open-question picks are baked in (54px btn-gold, label-only Start, "PR/Training/Recovery" labels, whisper cold-cue, trophy/barbell/leaf mode icons, "NEXT NEARBY"). Updated per founder direction: the "Plan a route" flow is deleted entirely — the app is mode-first only.

PR mode shows a trophy chip and fires every cue type (approach=aggressive variant, start, splits on ±3s, end with PR gap). Same chip mechanism, different icon/label. "NEXT NEARBY" replaces "Next segment" for every ride — honest because Quick-Start loads all starred segments with no fixed order.

Key decisions baked into this mockup (Stencil's picks on all 10 open questions):
  • Start Ride = btn-gold 54px, label-only (no play icon) — confident without shouting over the feed.
  • ModeSelector reuses RouteSetup's goalChip/goalChipSelected verbatim. Labels "PR / Training / Recovery". Zero new tokens.
  • Plan-a-route flow removed entirely — the app is mode-first only. RouteSetup / PreRideBrief / route-matching / on-demand cue generation are all gone. Cues come from background pre-gen + the non-LLM fallback line.
  • Cold-cue = a whisper line under the button, never a banner, never disables Start.
  • In-Ride mode chip is gold-tinted, persistent, status-only (no in-ride switching). Icons: PR=trophy, Training=barbell, Recovery=leaf.
  • "NEXT NEARBY" two-line card (tiny label + big name) for all rides — glanceable on a bike mount.
  • Mode persists the instant a chip is tapped (sticky default + warms the preferred mode at next sync).
